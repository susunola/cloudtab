# cloudtab E2E Price Accuracy Test Design Document

## 1. Goals

For the **19 Tencent Cloud resource types** supported by cloudtab, verify each one for:

1. **API reachability** - the `PriceRequest` constructed by cloudtab is accepted by the real Tencent Cloud API and returns a valid price
2. **Price parsing correctness** - cloudtab's `Parse` function correctly extracts the price from the real API response
3. **Monthly cost calculation correctness** - cloudtab's conversion logic (hour -> month (x730), cents -> CNY (/100), discounted price selection, etc.) is correct

Each product is tested independently, producing the raw API request/response, cloudtab calculation results, and a comparison report.

## 3. File Format Specification

### 3.1 raw_price.json

One record per resource, containing the request sent by cloudtab and the raw response returned by Tencent Cloud:

```json
{
  "resource_address": "tencentcloud_instance.test_postpaid",
  "resource_type": "tencentcloud_instance",
  "timestamp": "2026-07-24T15:30:00+08:00",
  "request": {
    "product": "cvm",
    "action": "InquiryPriceRunInstances",
    "region": "ap-guangzhou",
    "params": {
      "Placement": {"Zone": "ap-guangzhou-3"},
      "ImageId": "img-d8216ykb",
      "InstanceType": "SA2.MEDIUM4",
      "InstanceChargeType": "POSTPAID_BY_HOUR",
      "InstanceCount": 1,
      "SystemDisk": {"DiskType": "CLOUD_PREMIUM", "DiskSize": 50}
    }
  },
  "response": {
    "raw": "{\"Response\":{\"Price\":{\"InstancePrice\":{\"UnitPrice\":0.04,\"UnitPriceDiscount\":0.03,\"ChargeUnit\":\"HOUR\"}}}}",
    "price_fields": {
      "UnitPrice": 0.04,
      "UnitPriceDiscount": 0.03,
      "ChargeUnit": "HOUR",
      "_unit": "CNY",
      "_path": "Response.Price.InstancePrice"
    }
  },
  "error": null
}
```

**Notes**:
- `response.raw` - the complete raw JSON from the SDK `ToJsonString()`
- `response.price_fields` - the key price fields extracted from raw (for manual inspection); `_unit` marks the unit (CNY/cents), `_path` marks the JSON path
- In multi-resource scenarios, `raw_price.json` is an array, with one element per resource

### 3.2 cloudtab_price.json

The cost components output by cloudtab's `Parse` function, matching the `ResourceCost` structure in `output.Report`:

```json
{
  "address": "tencentcloud_instance.test_postpaid",
  "type": "tencentcloud_instance",
  "components": [
    {
      "name": "Compute (SA2.MEDIUM4)",
      "unit": "HOUR",
      "hourly_cost": 0.03,
      "monthly_cost": 21.90,
      "currency": "CNY"
    }
  ]
}
```

## 4. run.go Architecture

### 4.1 Responsibilities

`run.go` is a standalone Go program (`package main`) that imports cloudtab's internal packages and performs the following flow:

> **Design decision (branch 1)**: run.go directly imports the internal packages (`parser`, `resources`, `pricing`) instead of invoking the `cloudtab breakdown` CLI binary. Rationale: run.go needs intermediate data such as `PriceRequest` (Extract output) and `raw []byte` (Query output) to generate `raw_price.json`, and the CLI does not expose this data. It has been confirmed that the `priceReport`/`priceResource` functions only perform orchestration (registry lookup, StaticMapper type assertion, error handling, concurrency) and do not involve price calculation logic, so directly calling the Extract->Query->Parse three-step pipeline goes through exactly the same price calculation code path as the CLI.

```
For each product directory:
  1. terraform init + plan + show -json -> plan.json
     (if terraform plan reports "Unsupported resource type" -> mark as "manual test required", skip)
  2. parser.LoadPlanJSON(plan.json) -> []PlannedResource
  3. For each PlannedResource:
     a. registry.Lookup(type) -> Mapper
     b. If it is a StaticMapper (type assertion) -> mapper.Estimate(resource) -> CostComponent
        (produces only cloudtab_price.json, not raw_price.json, no API call)
     c. Otherwise:
        i.  mapper.Extract(resource) -> PriceRequest          <- saved to raw_price.json.request
        ii. engine.Query(PriceRequest) -> raw []byte           <- saved to raw_price.json.response
        iii.mapper.Parse(PriceRequest, raw) -> []CostComponent <- saved to cloudtab_price.json
  4. Extract key price fields from the raw response -> fill raw_price.json.response.price_fields
  5. Compare price_fields vs cloudtab CostComponent -> generate report.md
  6. Print summary table
```

### 4.2 Core Data Structures

```go
// TestCase defines the E2E test configuration for one product
type TestCase struct {
    Name         string   // directory name, e.g. "cvm"
    ResourceType string   // Terraform type, e.g. "tencentcloud_instance"
    SkipTerraform bool    // true = skip terraform plan, use the existing plan.json directly
}

// RawPriceRecord stores the complete request-response chain for one resource
type RawPriceRecord struct {
    ResourceAddress string                 `json:"resource_address"`
    ResourceType    string                 `json:"resource_type"`
    Timestamp       string                 `json:"timestamp"`
    Request         map[string]interface{} `json:"request"`     // PriceRequest flattened
    Response        RawResponse            `json:"response"`
    Error           string                 `json:"error,omitempty"`
}

type RawResponse struct {
    Raw        string                 `json:"raw"`          // raw output of SDK ToJsonString()
    PriceFields map[string]interface{} `json:"price_fields"` // extracted key fields
}

// ProductValidator extracts price fields from the raw API response and defines validation rules
type ProductValidator interface {
    // ExtractPriceFields extracts key price fields from the raw JSON response
    ExtractPriceFields(raw []byte) map[string]interface{}
    // Validate compares the API price fields against cloudtab's CostComponent
    Validate(fields map[string]interface{}, comps []output.CostComponent) []CheckResult
}

type CheckResult struct {
    Name     string  // check name
    APIValue float64 // value returned by the API
    GotValue float64 // value calculated by cloudtab
    Formula  string  // calculation formula (e.g. "0.03x730=21.90")
    Status   string  // PASS | SUSPICIOUS | FAIL
    // PASS: abs(api-got) < 0.01 and api > 0
    // SUSPICIOUS: api == 0 (possible Response wrapper parsing bug)
    // FAIL: abs(api-got) >= 0.01
}
```

### 4.3 Product Validators

Each product needs a `ProductValidator` to define:
- which JSON path to extract price fields from
- how to compare the API value against the cloudtab value

Based on differences in API response structure and price fields, there are **14 independent validators** in total. Each validator notes in its comments which Mapper Parse function it mirrors, so that it can be updated in sync when Parse changes.

> **Validator-Mapper coupling note**: A validator is essentially replicating the Mapper's Parse logic (which field to extract, how to convert). This is an intentional coupling - only a field-by-field comparison can catch "wrong field read" bugs (such as reading `UnitPrice` instead of `UnitPriceDiscount`). The cost is that validators must be updated in sync when Parse changes.

| # | Validator | Covered products | Mirrored Parse function | Response path | Price unit | POSTPAID hourly cost source | PREPAID monthly cost source |
|---|---|---|---|---|---|---|---|
| 1 | cvmClbValidator | CVM, CLB | `CVMInstance.Parse` / `CLBInstance.Parse` | `Response.Price.InstancePrice` | CNY | `UnitPriceDiscount` | `DiscountPrice` |
| 2 | cbsValidator | CBS | `CBSStorage.Parse` | `Response.DiskPrice` | CNY | `UnitPriceDiscount` | `DiscountPrice` |
| 3 | cdbFenValidator | MySQL, PostgreSQL, MariaDB, SQLServer, DCDB | each own `Parse` (shared `parseTencentPrice`) | `Response.{Price, OriginalPrice}` | cents | `Price/100` | `Price/100` |
| 4 | redisValidator | Redis | `RedisInstance.Parse` | `Response.{Price, HighPrecisionPrice, AmountUnit}` | cents/micro-cents | `normalizeTencentAmount` | same as left |
| 5 | mongodbValidator | MongoDB | `MongoDBInstance.Parse` | `Response.Price` | CNY | `UnitPrice` | `DiscountPrice` |
| 6 | cynosdbValidator | CynosDB | `CynosDBCluster.Parse` | `Response.{InstancePrice, StoragePrice}` | cents (int64) | `UnitPriceDiscount/100` (two components) | `TotalPriceDiscount/100` |
| 7 | lighthouseValidator | Lighthouse | `LighthouseInstance.Parse` | `Response.Price.InstancePrice` | CNY | none (monthly only) | `DiscountPrice` |
| 8 | ecmValidator | ECM | `ECMInstance.Parse` | `Response.InstancePrice` | cents (uint64) | `DiscountPrice/100` | none (POSTPAID only) |
| 9 | gaapValidator | GAAP | `GAAPProxy.Parse` | `Response.{ProxyDailyPrice, DiscountProxyDailyPrice}` | CNY/day | none (daily -> month) | `DiscountProxyDailyPrice x daysPerMonth` |
| 10 | vpnValidator | VPN | `VPNGateway.Parse` | `Response.Price.{InstancePrice, BandwidthPrice}` | CNY | `UnitPrice` (note: not UnitPriceDiscount) | `DiscountPrice` |
| 11 | staticValidator | EIP | `EIP.Estimate` | no API | - | - | - |
| 12 | cwpValidator | CWP | `YunjingLicense.Parse` | `Response.{OriginalPrice, DiscountPrice}` | CNY | none (monthly only) | `preferDiscount(DiscountPrice, OriginalPrice)` |
| 13 | cloudhsmValidator | CloudHSM | `CloudHSMInstance.Parse` | `Response.{TotalCost, OriginalCost}` | CNY | none (monthly only) | `TotalCost` (fallback `OriginalCost`) |
| 14 | domainValidator | Domain | `DomainRegistration.Parse` | `Response.PriceList[].{RealPrice, Price}` | CNY/year | none (/12 -> month) | `RealPrice/12` (fallback `Price/12`) |

**Key differences to note**:
- Validators 1-2 (CVM/CBS/CLB) use `UnitPriceDiscount` (discounted price), while validators 5/10 (MongoDB/VPN) use `UnitPrice` (list price) - the validator must stay consistent with the Mapper
- Validator 6 (CynosDB) has two components (instance + storage), which must be verified separately
- Validator 9 (GAAP) is a daily price and must be converted to a monthly cost via x(730/24)
- Validator 11 (EIP) makes no API call and only verifies the structure of the components returned by Estimate

### 4.4 Execution Flow

```
main()
  ├── Parse arguments (--products=cvm,mysql or --all)
  ├── Initialize pricing.Engine (read TENCENTCLOUD_SECRET_ID/KEY, NoCache=true)
  ├── Iterate over the TestCase list
  │   ├── If plan.json does not exist -> run terraform init/plan/show
  │   │   └── If terraform plan reports "Unsupported resource type"
  │   │       -> mark as "manual test required", skip this product
  │   ├── parser.LoadPlanJSON(plan.json)
  │   ├── For each resource:
  │   │   ├── registry.Lookup(type) -> Mapper
  │   │   ├── StaticMapper type assertion:
  │   │   │   ├── Is StaticMapper -> mapper.Estimate(resource) -> CostComponents
  │   │   │   │   (produces only cloudtab_price.json, not raw_price.json, no API call)
  │   │   │   └── No -> mapper.Extract(resource) -> PriceRequest
  │   │   │       ├── engine.Query(PriceRequest) -> raw response
  │   │   │       ├── mapper.Parse(PriceRequest, raw) -> CostComponents
  │   │   │       ├── save raw_price.json
  │   │   │       └── save cloudtab_price.json
  │   │   └── (API error -> record in raw_price.json.error, mark as "API ERROR", does not affect other products)
  │   ├── Run ProductValidator -> generate CheckResults (including > 0 precondition + floating-point tolerance)
  │   └── Generate report.md
  └── Print summary table (PASS/SUSPICIOUS/FAIL/API_ERROR/MANUAL for all products)
```

## 6. Verification Rules Summary

### 6.1 General Rules

| Rule | Formula | Applicable scenario |
|---|---|---|
| **API price > 0** | `API_price > 0`, otherwise mark SUSPICIOUS | precondition for all products |
| **Floating-point tolerance** | `abs(api - cloudtab) < 0.01` (absolute error < 1 cent) | all numeric comparisons |
| cents -> CNY | `priceYuan = priceFen / 100` | MySQL/PostgreSQL/MariaDB/SQLServer/DCDB/CynosDB/ECM |
| hour -> month | `monthly = hourly x 730` | all POSTPAID products |
| day -> month | `monthly = daily x (730/24)` | GAAP |
| discount preference | `effective = DiscountPrice > 0 ? DiscountPrice : OriginalPrice` | PREPAID products |
| PREPAID has no hourly cost | `hourly = 0` | all PREPAID products |

> **> 0 precondition note**: If the price field returned by the API is 0 (e.g. `UnitPriceDiscount=0`, `DiscountPrice=0`), it means the API may not have returned the price correctly (such as a recurrence of the Response wrapper parsing bug). In that case `0 == 0` would produce a false positive, so the API price > 0 must be checked before the numeric comparison. If the API price is 0, that check is marked as `SUSPICIOUS` instead of `PASS`.

> **Floating-point tolerance note**: float64 arithmetic may produce tiny errors (such as `0.03 x 730 = 21.900000000000002`), so all numeric comparisons use the `abs(api - cloudtab) < 0.01` tolerance. 0.01 CNY (1 cent) is enough to cover float64 precision errors while not masking real calculation errors.

### 6.2 Verification Rules per Validator

> All `==` comparisons below use the `abs(api - cloudtab) < 0.01` tolerance. All API price fields must first pass the > 0 precondition.

**Validator 1 (CVM, CLB)** - `Response.Price.InstancePrice`:
```
precondition: UnitPriceDiscount > 0 (POSTPAID) or DiscountPrice > 0 (PREPAID)
POSTPAID (ChargeUnit=HOUR):
  abs(hourly_cloudtab - UnitPriceDiscount) < 0.01
  abs(monthly_cloudtab - hourly x 730) < 0.01
PREPAID (ChargeUnit=MONTH):
  abs(monthly_cloudtab - DiscountPrice) < 0.01
  hourly_cloudtab == 0
```

**Validator 2 (CBS)** - `Response.DiskPrice`:
```
same as validator 1, except the path changes from Price.InstancePrice to DiskPrice
```

**Validator 3 (MySQL, PostgreSQL, MariaDB, SQLServer, DCDB)** - `Response.{Price, OriginalPrice}` (cents):
```
precondition: Price > 0
POSTPAID:
  abs(hourly_cloudtab - Price / 100) < 0.01
  abs(monthly_cloudtab - hourly x 730) < 0.01
PREPAID:
  abs(monthly_cloudtab - Price / 100) < 0.01
  hourly_cloudtab == 0
```

**Validator 4 (Redis)** - `Response.{Price, HighPrecisionPrice, AmountUnit}`:
```
precondition: normalizeTencentAmount(Price|HighPrecisionPrice, AmountUnit) > 0
priceYuan = normalizeTencentAmount(Price|HighPrecisionPrice, AmountUnit)
POSTPAID (BillingMode=0):
  abs(hourly_cloudtab - priceYuan) < 0.01
  abs(monthly_cloudtab - priceYuan x 730) < 0.01
PREPAID (BillingMode=1):
  abs(monthly_cloudtab - priceYuan) < 0.01
```

**Validator 5 (MongoDB)** - `Response.Price` (CNY):
```
precondition: UnitPrice > 0 (POSTPAID) or DiscountPrice > 0 (PREPAID)
POSTPAID: abs(hourly_cloudtab - UnitPrice) < 0.01, abs(monthly - hourly x 730) < 0.01
PREPAID:  abs(monthly_cloudtab - DiscountPrice) < 0.01, hourly == 0
```

**Validator 6 (CynosDB)** - `Response.{InstancePrice, StoragePrice}` (cents, int64, two components):
```
precondition: InstancePrice.UnitPriceDiscount > 0 (POSTPAID) or InstancePrice.TotalPriceDiscount > 0 (PREPAID)
POSTPAID: instance component hourly=UnitPriceDiscount/100, monthly=hourly x 730
          storage component likewise (StoragePrice path)
PREPAID:  instance component monthly=TotalPriceDiscount/100, storage component likewise
```

**Validator 7 (Lighthouse)** - `Response.Price.InstancePrice` (CNY, monthly only):
```
precondition: DiscountPrice > 0
abs(monthly_cloudtab - DiscountPrice) < 0.01, hourly == 0
```

**Validator 8 (ECM)** - `Response.InstancePrice` (cents, uint64, POSTPAID only):
```
precondition: DiscountPrice > 0
abs(hourly_cloudtab - DiscountPrice/100) < 0.01, abs(monthly - hourly x 730) < 0.01
```

**Validator 9 (GAAP)** - `Response.{ProxyDailyPrice, DiscountProxyDailyPrice}` (CNY/day):
```
precondition: DiscountProxyDailyPrice > 0 (or ProxyDailyPrice > 0 as fallback)
abs(monthly_cloudtab - DiscountProxyDailyPrice x daysPerMonth) < 0.01, hourly == 0
```

**Validator 10 (VPN)** - `Response.Price.{InstancePrice, BandwidthPrice}` (CNY):
```
precondition: InstancePrice.UnitPrice > 0 (POSTPAID) or DiscountPrice > 0 (PREPAID)
POSTPAID: abs(hourly_cloudtab - UnitPrice) < 0.01, abs(monthly - hourly x 730) < 0.01
          (note: VPN uses UnitPrice instead of UnitPriceDiscount)
PREPAID:  abs(monthly_cloudtab - DiscountPrice) < 0.01, hourly == 0
```

**Validator 11 (EIP, StaticMapper)**:
```
no API call, verifies that Estimate returns:
  - at least 1 CostComponent
  - MonthlyCost == 0 (placeholder)
  - Currency non-empty
```

**Validator 12 (CWP, YunjingLicense)** - `Response.{OriginalPrice, DiscountPrice}` (CNY):
```
precondition: DiscountPrice > 0 or OriginalPrice > 0
monthly = preferDiscount(DiscountPrice, OriginalPrice)  # CNY, not divided by 100
abs(monthly_cloudtab - apiMonthly) < 0.01
hourly == 0 (always PREPAID)
```

**Validator 13 (CloudHSM)** - `Response.{TotalCost, OriginalCost}` (CNY):
```
precondition: TotalCost > 0 or OriginalCost > 0
monthly = TotalCost > 0 ? TotalCost : OriginalCost  # CNY, not divided by 100
abs(monthly_cloudtab - apiMonthly) < 0.01
hourly == 0 (always PREPAID)
note: the field names are TotalCost/OriginalCost, not Price/OriginalPrice
```

**Validator 14 (Domain)** - `Response.PriceList[].{RealPrice, Price}` (CNY/year):
```
precondition: RealPrice > 0 or Price > 0
yearly = RealPrice > 0 ? RealPrice : Price  # CNY/year (domainPriceUnitDivisor=1)
monthly = yearly / 12
abs(monthly_cloudtab - apiMonthly) < 0.01
hourly == 0
```

- FAIL -> exit code 1 (usable in CI)

## 8. Notes

### 8.1 Challenges with the Terraform Configuration

For some products, the Terraform provider field names may not match the field names read by cloudtab's Extract (such as `available_zone` vs `availability_zone`). `run.go` should read fields from `resource_changes[].change.after` in `plan.json` rather than relying on the Terraform provider's schema documentation.

For products with uncertain fields, first run `terraform plan` to generate plan.json, inspect the actual field names in `after`, and then cross-check against the Mapper's Extract function.

### 8.2 TF Provider Support Detection

Not all resource types exist in the Tencent Cloud Terraform provider. `run.go` detects this automatically during the `terraform plan` stage:
- If `terraform plan` reports the error "Unsupported resource type" -> the product is marked as "manual test required" and the test is skipped
- If `terraform plan` succeeds -> continue with the Extract->Query->Parse flow
- If the API call returns an error (such as an invalid bundle_id) -> record it in the `error` field of `raw_price.json` and mark it as "API ERROR"

Products not supported by TF plan can still be tested via a hand-written `plan.json` (using the `--skip-terraform` argument).

### 8.3 Cache Interference

run.go must initialize pricing.Engine with `NoCache: true`. Otherwise it may return stale prices from the previous run's BoltDB cache (`~/.cloudtab/cache.db`) instead of the real API response. The cache would mask API price changes, rendering the E2E test meaningless.

### 8.4 Known Response Wrapper Issue

This round of testing has already fixed the bug where the three Mappers CVM/CBS/CLB did not read the `Response` wrapper. The other Mappers (MongoDB, CynosDB, Lighthouse, ECM, GAAP, VPN, Redis, Yunjing, CloudHSM, Domain) already handle the `Response` path correctly. The E2E test will verify that all Mappers can read prices correctly under the real API.
